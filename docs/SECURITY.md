# Security Architecture & Production Threat Model

This document outlines the security controls, boundary guarantees, and residual risks of running `api-sandbox-links` in production.

---

## 1. Trust Boundaries & Design Intent

`api-sandbox-links` is engineered for **trusted and semi-trusted workloads**:
- Take-home engineering interviews
- Ephemeral pull request previews and code reviews
- Bug reproduction environments
- Hands-on workshops and demos

> **Important:** The platform is **not** currently designed for hostile public multi-tenancy without additional container virtualization (such as gVisor or Firecracker). Untrusted public users should not be granted arbitrary repository execution without sandboxed worker isolation.

---

## 2. Active Security Controls

### 2.1 Container Sandboxing & Isolation
Every sandbox app container is launched with strict containment in [`backend/internal/orchestrator/lifecycle.go`](file:///home/swordrookie/projects/api_sandbox_links/api-sandbox-links/backend/internal/orchestrator/lifecycle.go):

| Control | Implementation | Purpose |
|---|---|---|
| **Capability Dropping** | `CapDrop: ["ALL"]` | Drops every Linux capability by default (`SYS_ADMIN`, `NET_RAW`, etc.). `CapAdd: ["NET_BIND_SERVICE"]` is retained to permit binding port 80. |
| **No Setuid Escalation** | `SecurityOpt: ["no-new-privileges:true"]` | Prevents setuid binaries or file capabilities inside the image from escalating privileges. |
| **Process Supervision** | `Init: true` (tini) | Reaps zombie child processes generated by Node.js, Python, or Ruby forks. |
| **Resource Quotas** | Memory (512MB), Swap (512MB, no swap), NanoCPUs (75% core), PIDs Limit (256) | Prevents runaway workloads or fork bombs from starving the host. |
| **Network Isolation** | Dedicated private bridge `sandbox_<id[:8]>` | Sandboxes cannot communicate with other sandboxes or reach the host Docker daemon directly. |
| **Strict Hardening (Opt-in)** | `SANDBOX_HARDENED=true` | Read-only root filesystem (`ReadonlyRootfs: true`) with ephemeral `tmpfs` at `/tmp` (`size=64m,noexec,nosuid`). |
| **Kernel Isolation (Opt-in)** | `SANDBOX_RUNTIME="runsc"` | Redirects execution through Google gVisor kernel interceptor when installed on the host. |

### 2.2 Build Phase Isolation
- **Environment Allowlisting:** Child processes for both Nixpacks and Railpack run under a strict deny-by-default environment (`nixpacksEnv` and `railpackEnv`). Platform secrets, database credentials, and Docker host tokens are stripped.
- **Build Semaphore:** Builds are bounded by `BUILD_CONCURRENCY` (default 2) to prevent compile storms from degrading active container responsiveness.

### 2.3 Edge & Gateway Protection
- **Single-Flight Wake Concurrency:** Duplicate requests to hibernated containers are coalesced into a single wake operation, preventing container flapping and boot storms.
- **Rate Limiting:** Token-bucket rate limiting on the gateway listener (:8090) mitigates Layer 7 request floods (configurable via `GATEWAY_RATE_LIMIT_RPS` and `GATEWAY_RATE_LIMIT_BURST`).
- **Payload Limits:** `MaxBytesReader` caps inbound request bodies to 32MB by default.
- **Wildcard TLS & Strict Headers:** Traefik terminates TLS using automated Let's Encrypt certificates with HSTS (`max-age=31536000`), `nosniff`, and origin isolation.

## 3. Residual Risks & Operational Trade-offs

1. **Shared Linux Kernel (Default Runtime):**
   - Standard Docker containers share the host Linux kernel. A zero-day kernel privilege escalation vulnerability could theoretically allow a container breakout.
   - *Mitigation:* Deploy on hosts with gVisor (`SANDBOX_RUNTIME="runsc"`), or restrict deployments to semi-trusted developers and candidates.
2. **Build-Phase Code Execution:**
   - Package managers (e.g., `npm postinstall`, `setup.py`, `Cargo.build`) execute arbitrary build scripts during image generation.
   - *Mitigation:* Child environment sanitization removes platform secrets. BuildKit rootless daemon prevents build hooks from accessing host root privileges.
3. **Outbound Network Egress:**
   - Running sandboxes have outbound network access by default (needed for downloading third-party APIs, NPM packages, or external database queries).
   - *Mitigation:* Apply host-level `iptables` or cloud firewall security groups if network egress must be restricted.
4. **Sidecar Database Shared Network:**
   - A sandbox's app container and its sidecar DB share the private bridge network `sandbox_<id[:8]>`.
   - *Mitigation:* Database credentials are encrypted with AES-256-GCM at rest and injected uniquely per sandbox. The network is torn down immediately upon sandbox expiration.
